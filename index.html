01 — De opdracht

In 6 lijnen

Vat je de opdracht samen voor iemand die niets van het vak kent, dan zeg je dit:

  1. Je maakt een portfolio website over jezelf, waarin je je schoolwerk en ander grafisch werk toont.
  2. Je begint met research en een moodboard: naar welke sites kijk je graag, en waarom?
  3. Je ontwerpt in Figma — drie versies: desktop, tablet, smartphone.
  4. We doen een peer evaluatie in de klas: jij geeft feedback, je krijgt feedback en je verwerkt die.
  5. Je bouwt de site met HTML, CSS en een beetje JavaScript. Responsive, met eigen afbeeldingen, minstens één eigen video, een werkend contactformulier en een footer.
  6. Je test, valideert en presenteert. Je kan elke regel code uitleggen. Klaar = online.

Wat is "grafisch werk"?

Alles wat je visueel maakte in je schoolcarrière: posters, logo's, illustraties, foto's, mock-ups, 3D-renders, UI-schetsen, magazinespreads, animaties, storyboards. Ook werk uit vorige jaren en uit je vrije tijd.

Waarom een portfolio?

Een portfolio is je visitekaartje: voor een stageplaats, een vervolgopleiding of een freelancerklant. Het toont niet alleen wat je maakt, maar ook hoe je denkt. Dit is dus geen oefening — dit is je eerste echte online profiel.

Wat telt als "af"?

Een site zonder Figma-ontwerp is niet af. Een Figma-ontwerp zonder code is niet af. Een site die alleen op jouw laptopscherm werkt, is niet af. Alle drie de onderdelen tellen mee in je punt.

Inleveren via GitHub — zo werkt het

  1. Maak een publieke repository aan met de naam 6cm-portfolio-voornaam.
  2. Clone hem lokaal, zet je project erin en commit minstens na elke werkdag. Je commitgeschiedenis is je procesbewijs.
  3. Zet GitHub Pages aan: Settings → Pages → Deploy from a branch → main / root.
  4. Test de online link in een incognitovenster én op je gsm.
  5. Bezorg de leerkracht je repositorylink én je Pages-link, met in de README je naam, klas en de link naar je Figma-ontwerp.

Let op: je repository moet openbaar staan, anders kan je werk niet bekeken of beoordeeld worden. De leerkracht kijkt ook naar je commits — een repository met één commit van 200 bestanden vertelt niets over je proces.

03 — Stappenplan

Acht fasen, één site

Klik een fase open. Elke fase heeft een tijdsinschatting en een duidelijke "klaar als…". Werk je sneller? Ga verder. Werk je trager? Dan weet je meteen waar je achterloopt.

FASE 00Kick-off & research± 45 min

Voor je één pixel tekent, kijk je rond. Verzamel minstens 5 portfolio-sites die je sterk vindt en 3 die je zwak vindt.

  • Maak een FigJam of een pagina in je Figma-bestand: per site een screenshot + 2 regels uitleg (wat werkt, wat niet).
  • Maak een moodboard: kleuren, typografie, sfeer, texturen. Minstens 12 beelden.
  • Schrijf je one-liner op: in één zin, wat maakt jouw werk bijzonder? Die zin komt in je jumbotron.
  • Volg de Figma-beginnerscursus (verplicht, ± 1,5 uur) vóór je aan fase 02 begint.
Klaar als… je 8 sites hebt geanalyseerd, een moodboard hebt en je one-liner op papier staat.
FASE 01Content verzamelen± 60 min

Een portfolio zonder werk is een lege kast. Verzamel je materiaal vóór je gaat ontwerpen — anders ontwerp je voor gaten.

  • Minstens 6 werken voor je portfolio, waarvan minstens 3 met een eigen projectdetailpagina.
  • Per werk: titel, jaar, opdracht/tools, korte beschrijving (2–4 zinnen) en 1–4 beelden.
  • Eén video die je zelf maakte tijdens je schooljaren (animatie, montage, motion design, behind-the-scenes). Max. 60 seconden, onder 25 MB.
  • Een profielfoto of een zelfportret/illustratie van jezelf voor het "over mij"-deel.
Klaar als… je een map /content hebt met alle beelden, je video en een tekstbestand met alle titels en beschrijvingen.
FASE 02Figma: wireframe → 3 ontwerpen± 3 lesblokken

Je werkt mobile first: eerst het kleinste scherm, dan groter. Zo dwing je jezelf om prioriteiten te stellen.

  • Stap 1 — Wireframe (grijs, geen kleur): drie frames naast elkaar, alleen kaders en blokken. Hier bepaal je de structuur, niet de look.
  • Stap 2 — Systeem: kies je kleurenpalet (max. 4 kleuren), twee lettertypes, een type-scale en een spacing-schaal van 8px.
  • Stap 3 — High fidelity: werk de drie frames volledig uit met echte content. Gebruik Auto Layout, Components en Variants — niet alles met de hand.
  • Stap 4 — Prototype: koppel minstens de navigatie en het mobiele menu, zodat je kan doorklikken.
Klaar als… je drie frames hebt (1440 / 768 / 390 px breed) die samen één samenhangend ontwerp vormen, een componentenbibliotheek hebt en je kan doorklikken in presentatiemodus.
FASE 03Peer evaluatie in de klas± 50 min

Je design gaat de kamer rond. Drie rondes, telkens met een andere klasgenoot. Je kijkt samen naar het scherm in presentatiemodus en gebruikt het feedbackformulier uit deel 06.

  • Je geeft zelf ook feedback aan 3 anderen. Feedback geven is een vaardigheid die meetelt.
  • Geen "ik vind het mooi". Wel: "de CTA valt weg omdat de achtergrond even fel is als de knop".
  • Na de les kies je 3 aanpassingen die je écht doorvoert. Je hoeft niet alles te doen — je moet wel kiezen en uitleggen.
Klaar als… je 3 formulieren hebt ontvangen, 3 hebt ingevuld, en je top-3 aanpassingen in je Figma-bestand verwerkt zijn.
FASE 04Code: structuur & semantiek± 2 lesblokken

Je start met HTML — deftig, semantisch, zonder <div class="header"> waar een <header> hoort.

  • Zet je bestandsstructuur op en maak je GitHub-repository aan (zie deel 07).
  • Bouw de volledige inhoud van de homepage, één projectdetailpagina en het contactformulier in HTML.
  • Alle afbeeldingen krijgen een alt, alle invoervelden een <label>, koppen gaan in volgorde (één h1 per pagina).
  • Nog géén CSS. Een site die zonder stylesheet logisch leest, is een goede site.
Klaar als… je HTML door de validator van W3C geraakt zonder fouten en de pagina zonder CSS nog steeds begrijpelijk is.
FASE 05Code: responsive CSS± 3 lesblokken

Nu komt het echte werk. Je bouwt mobile first en schaalt op met media queries — exact dezelfde drie schermen als in je Figma-ontwerp.

  • Werk met custom properties (CSS-variabelen) voor kleur, spacing en typografie.
  • Gebruik Flexbox voor rijen en CSS Grid voor de portfolio-grid.
  • Bouw de responsive navigatie volgens mini-cursus 07.A.
  • clamp() voor vloeiende typografie, min()/max() waar het kan — geen 40 media queries.
Klaar als… je site op 390px, 768px en 1440px breed werkt, geen horizontale scrollbalk heeft en er op alle drie uitziet zoals in je ontwerp.
FASE 06Beeld, video & formulier± 2 lesblokken

Media maken of breken je site. Een 8 MB foto is een dode site op een gsm met 3G.

  • Comprimeer alle beelden: JPG of WebP, max. 1600px breed, streef naar < 300 KB per beeld.
  • Gebruik srcset en sizes, plus loading="lazy" voor alles onder de fold.
  • Plaats je video met <video> (geen YouTube-embed voor je eigen werk), met een posterbeeld en ondertitels.
  • Maak het contactformulier af: labels, verplichte velden, foutmeldingen, focus-states.
Klaar als… je video speelt op een gsm, je pagina onder de 3 MB blijft en je formulier je tegenhoudt als je een veld leeg laat.
FASE 07Testen, valideren, online zetten± 1 lesblok

Dit is de fase die het verschil maakt tussen een 12 en een 17.

  • Validatie: HTML en CSS door de W3C-validators. Los elke fout op.
  • Lighthouse: draai een audit in Chrome DevTools. Doel: Performance ≥ 85, Accessibility ≥ 90.
  • Toegankelijkheid: test met alleen je toetsenbord (Tab), check je contrasten (min. 4,5:1) en je alt-teksten.
  • Test op echt materiaal: open je site op je eigen smartphone. Niet in een verkleind browservenster.
  • Publiceer via GitHub Pages en test de online link in een incognitovenster.
  • Lever in: commit alles, push naar GitHub en bezorg je repositorylink én je Pages-link.
Klaar als… je 0 validatorfouten hebt, je Lighthouse-scores gehaald zijn, je online link werkt op een toestel dat niet van jou is en je repository up-to-date is gepusht.
04 — De checklist

Alles wat erin moet

Dit is geen inspiratielijst, dit is de meetlat. Vink af terwijl je bouwt. Je mag dit blok afdrukken en naast je toetsenbord leggen.

Structuur — de blokken van je pagina

Design — uit Figma

Techniek — onder de motorkap

Niet "Welkom" — maar dit

"Welkom op mijn website" is de meest voorkomende en minst interessante zin op het internet. Iedereen kan hem schrijven, hij zegt niets over jou en hij vult je duurste ruimte: de eerste seconden van je bezoeker. Schrijf iets dat alleen over jouw werk kan gaan. Kies één van deze vijf vertrekpunten:

1 · De claim

"Ik maak posters die je van de gangmuren plukt."

2 · De vraag

"Wat gebeurt er als je een affiche in drie seconden moet begrijpen?"

3 · Het getal

"Zeventien posters, vier jaar, één stylo die het overleefde."

4 · Het statement

"Zwart-wit, veel lawaai, geen logo in een cirkel."

5 · De beschrijving

"Twaalf maanden beeld: foto's, posters en één mislukte 3D-render die ik toch toon."

En niet dit

"Welkom op mijn portfolio website! Ik ben een student en ik hou van design."

Je zin moet ook werken als jumbotron: kort genoeg om groot te zetten, concreet genoeg om te blijven hangen. Test hem op je buur: als die meteen kan zeggen over wie het gaat, zit je goed.

De drie breakpoints

Smartphone390 px
  • Eén kolom, alles onder elkaar
  • Hamburger-menu (niet zichtbaar op desktop)
  • Grid: 1 kolom, grote beelden
  • Typografie via clamp(), geen vaste px
  • CTA-knop over volle breedte
Tablet768 px

  • Grid: 2 kolommen
  • Navigatie zichtbaar of compact menu
  • Meer witruimte, grotere marges
  • Video over volle breedte

05 — Ontwerpen in Figma

Eerst je muis, dan je toetsenbord

Je ontwerpt in Figma Design (het gratis Starter-plan volstaat — je hebt geen betalende functies nodig voor deze opdracht). Nieuw met Figma? Volg eerst de officiële beginnerscursus hieronder. Die kost je ongeveer 1,5 uur en maakt de rest van de opdracht twee keer zo makkelijk.

De officiële Figma-cursus

Figma leert je in zijn eigen, gratis cursus "Figma Design for beginners" stap voor stap hoe je frames, Auto Layout, componenten en een klikbaar prototype maakt — inclusief het ontwerpen van een portfolio-website. Reken op een tiental tot twintigtal korte video's.

Start de Figma-cursus ↗

help.figma.com/hc/en-us/sections/30880632542743-Figma-Design-for-beginners

Verplichte Figma-skills

  • Frames met vaste afmetingen (1440 / 768 / 390)
  • Auto Layout — minstens in je header, kaarten en knoppen
  • Components + Variants — bv. knop: default / hover / mobile
  • Layout grid (kolommen + goot) per frame
  • Variables of styles voor kleur en typografie
  • Prototype-links tussen je frames
  • Netjes benoemde lagen — geen Frame 427

Zo pak je de drie frames aan

  1. Begin met het kleinste frame

    Maak een frame van 390 × 844 (iPhone-formaat). Ontwerp hier je volledige homepage. Alles wat je hier niet kwijt kan, is waarschijnlijk ook niet essentieel.

  2. Schaal op naar tablet

    Kopieer je mobiele frame naar 768 × 1024 en herbouw de layout. Gebruik Auto Layout zodat blokken zich aanpassen in plaats van ze met de hand te verslepen.

  3. Werk af op desktop

    Frame van 1440 × 1024. Container max. 1200px breed, met echte marges. Hier mag je experimenteren met een asymmetrische editorial layout voor de portfolio-grid.

  4. Ontwerp ook je projectdetailpagina en je formulier

    Niet alleen de homepage. Je detailpagina en je contactformulier hebben eigen uitdagingen (leesbaarheid, veldgroottes, focus-states). Ontwerp ze minstens op desktop en mobiel.

Ontwerp wat je kan bouwen

06 — Peer evaluatie

Drie rondes, drie critici

Je design wordt in de klas geëvalueerd door je medeleerlingen — vóór je begint te coderen, wanneer aanpassen nog goedkoop is. Je geeft zelf ook drie keer feedback. Dat telt mee in je procesevaluatie.

Ronde 1 · De eerste indruk

Je toont je desktop-frame 15 seconden zonder uitleg. De ander zegt wat hij ziet en onthoudt. Daarna pas jij je bedoeling. Als het verschil groot is, is je hiërarchie niet duidelijk genoeg.

Ronde 2 · De drie schermen

Samen doorloop je desktop, tablet en smartphone. De vraag is niet "is het mooi" maar "wat gebeurt er met dit blok als het scherm smaller wordt?"

Ronde 3 · De CTA-test

Je partner moet binnen 5 seconden de belangrijkste knop van je pagina aanwijzen. Kan hij dat niet, dan moet je contrast, grootte of positie herzien.

07.A — Mini-cursus

Responsive navigatie

Vier korte lessen: van een simpele hamburger tot een menu dat op elk scherm klopt, met Escape werkt en toegankelijk is. Dit is het onderdeel waar bijna elke portfolio op stukloopt — en het is tegelijk het eerste wat een bezoeker gebruikt.

Wat je leert

  • Een menu dat op mobiel dicht is en op desktop open
  • Openen en sluiten met een echte <button>
  • Escape, klik buiten het menu, focus terug
  • Zichtbaar waar je je bevindt (aria-current)

Nodig

Je HTML-basis uit fase 04. Geen framework, geen library — alleen CSS en een handvol JavaScript. Reken op 45 minuten om alles zelf te bouwen.

Extra theorie

De cursus Responsive Design van de vakgroep heeft een volledige module over dit onderwerp.

Module 10 · Responsive Navigatie ↗

Les 1 — Structuur: een knop, een nav, niets meer

Begin met de DOM. De knop staat vóór de <nav>, zodat de leesvolgorde voor een schermlezer klopt: eerst "menu", dan de links.

<!-- HTML: de volgorde is belangrijk -->
<header class="site-header">
  <a class="logo" href="index.html">JOUW NAAM</a>

  <button
    class="menu-toggle"
    type="button"
    aria-expanded="false"
    aria-controls="hoofdmenu">
    <span class="sr-only">Menu</span>
    <span class="bars" aria-hidden="true"></span>
  </button>

  <nav class="nav" id="hoofdmenu" aria-label="Hoofdnavigatie">
    <ul class="nav__list">
      <li><a href="index.html" aria-current="page">Home</a></li>
      <li><a href="#over">Over mij</a></li>
      <li><a href="#werk">Werk</a></li>
      <li><a href="#contact">Contact</a></li>
    </ul>
  </nav>
</header>
i
Waarom een <button> en geen <div>?

Een <button> is met het toetsenbord bereikbaar (Tab), reageert op Enter én Spatie, en wordt door schermlezers als knop aangekondigd. Een <div> met een click-listener doet niets van dat alles.

Wat de aria-attributen doen:

  • aria-expanded="false" — vertelt of het menu open of dicht is. JavaScript zet dit op "true".
  • aria-controls="hoofdmenu" — koppelt de knop aan het element dat hij bedient.
  • aria-current="page" — markeert de link naar de pagina waar je nu bent.

Les 2 — CSS: dicht op mobiel, open op desktop

Mobile first: eerst de kleine versie, dan opschalen met min-width. Op mobiel is het menu standaard verborgen en verschijnt het pas met de klasse .is-open.

/* CSS — mobile first */
.site-header {
  display: flex;
  align-items: center;
  justify-content: space-between;
  flex-wrap: wrap;
  padding: 1rem;
}

/* Mobiel: menu dicht, knop zichtbaar */
.nav { display: none; flex-basis: 100%; }
.nav.is-open { display: block; }

.nav__list {
  list-style: none;
  margin: 0;
  padding: 0;
  display: grid;
}

.nav__list a {
  display: block;
  padding: 0.75rem 0;
  text-decoration: none;
}

/* De link naar de huidige pagina */
.nav__list a[aria-current="page"] {
  font-weight: 700;
  text-decoration: underline;
  text-underline-offset: 4px;
}

/* Vanaf 768px: menu altijd zichtbaar, knop weg */
@media (min-width: 768px) {
  .menu-toggle { display: none; }
  .nav { display: block; flex-basis: auto; }
  .nav__list { display: flex; gap: 1.5rem; }
}
!
De valkuil van de twee schermen

Als je het menu opent op mobiel en dan het browservenster breder sleept, staat .is-open nog op de nav. Dat is geen probleem — want vanaf 768px toont de media query het menu toch, ongeacht de klasse. Zet daar dus géén display:none op .is-open.

Omgekeerd: ga je van breed naar smal, dan kan het menu onverwacht openstaan. Daarom zetten we de klasse bij het wijzigen van de schermbreedte terug (zie les 3).

Les 3 — JavaScript: open, dicht, Escape, buiten klikken

Alles wat je nodig hebt, staat hieronder. Lees het van boven naar onder: eerst de toggle, dan de drie manieren om te sluiten, dan het opruimen bij een groter scherm.

// js/nav.js
const toggle = document.querySelector('.menu-toggle');
const nav    = document.querySelector('#hoofdmenu');

// Eén functie die de staat zet: knop én menu samen
function setMenu(open) {
  toggle.setAttribute('aria-expanded', String(open));
  nav.classList.toggle('is-open', open);
}

function isOpen() {
  return toggle.getAttribute('aria-expanded') === 'true';
}

// 1. Openen en sluiten met de knop
toggle.addEventListener('click', () => setMenu(!isOpen()));

// 2. Sluiten met Escape, focus terug naar de knop
document.addEventListener('keydown', (e) => {
  if (e.key === 'Escape' && isOpen()) {
    setMenu(false);
    toggle.focus();
  }
});

// 3. Sluiten na een klik op een link (voor ankers op dezelfde pagina)
nav.addEventListener('click', (e) => {
  if (e.target.closest('a')) setMenu(false);
});

// 4. Sluiten als je naast het menu klikt
document.addEventListener('click', (e) => {
  if (!isOpen()) return;
  if (!nav.contains(e.target) && !toggle.contains(e.target)) {
    setMenu(false);
  }
});

// 5. Opruimen bij een breder scherm
const breed = window.matchMedia('(min-width: 768px)');
breed.addEventListener('change', (e) => {
  if (e.matches) setMenu(false);
});
✓
Waarom dit robuust is

Alle state zit op één plaats: aria-expanded op de knop. De klasse volgt die state, niet omgekeerd. Daardoor kunnen HTML en JavaScript nooit uit elkaar lopen — en een schermlezer leest precies hetzelfde als wat je ziet.

i
Klein maar belangrijk

matchMedia is de nette manier om te reageren op een breakpoint in JavaScript: je herhaalt de waarde uit je CSS niet in een resize-listener met innerWidth.

Zet je script onderaan je pagina of gebruik defer, anders bestaat de knop nog niet wanneer het script loopt.

Les 4 — Varianten en afwerking

Zonder JavaScript

Een <details>-element doet het gratis: het opent en sluit zonder script. Nadeel: je hebt minder controle over de animatie.

<details class="nav">
  <summary>Menu</summary>
  <ul> … </ul>
</details>

Animeren

Laat het menu niet verspringen maar schuiven. Respecteer wel wie liever geen beweging ziet.

.nav {
  transform: translateY(-8px);
  opacity: 0;
  transition: .18s ease;
}
.nav.is-open {
  transform: none;
  opacity: 1;
}
@media (prefers-reduced-motion: reduce) {
  .nav { transition: none; }
}

Groter dan drie links?

Heb je meer dan vijf items, groepeer dan in plaats van te proppen. Op desktop mag je een paar secundaire links (Instagram, LinkedIn, cv) naar de footer verhuizen. Een horizontale nav met acht items wordt onleesbaar — ook op 1440px.

!
De vier klassieke fouten

1. Menu openen met style.display = 'block' en vergeten op te ruimen bij een breder scherm.

2. De knop verbergen met display:none in de móbiele CSS. Resultaat: niemand kan je menu ooit openen.

3. Geen focus-state. Tab door je pagina: je moet altijd zien waar je staat.

4. De knop staat ná de nav in de DOM in plaats van ervoor, waardoor toetsenbordgebruikers eerst langs alle links moeten voor ze bij de knop komen.

✓
Klaar als…

Je menu op 390px opent en sluit met de knop, sluit met Escape, sluit als je ernaast klikt, op 768px en breder automatisch horizontaal staat zonder dat de knop nog te zien is, en je met Tab door alle links geraakt zonder vast te lopen.

Afbeeldingsgrid:
masonry of editorial

Je werk staat of valt met de manier waarop je het toont. In deze mini-cursus kies je eerst je grid, dan maak je de kaart die erin komt, en tot slot zorg je dat het grid niet instort op een gsm.

Les 1 — Kies je grid in 1 minuut

Drie manieren, drie karakters
TechniekKarakterWanneer kiezen
Uniform grid
grid-template-columns		 Rustig, voorspelbaar, alle kaarten even groot Als je werk heel verschillend is van formaat en je rust wil. De veiligste optie, altijd goed.
Editorial grid
grid-column: span		 Asymmetrisch, magazine-achtig, met uitschieters Als je wil dat één werk de show steelt en de rest meeloopt. Meest "ontworpen" gevoel.

/* A — uniform responsive grid */
.gallery {
  display: grid;
  gap: 1rem;
  grid-template-columns: 1fr;
}
@media (min-width: 768px) {
  .gallery {
    grid-template-columns: repeat(2, 1fr);
  }
}
@media (min-width: 1200px) {
  .gallery {

  }
}

/* Het beeld zelf: nooit uitrekken */

  width: 100%;
  height: 100%;
  object-fit: cover;
  display: block;
}
/* B — editorial grid: 6 kolommen als basis */
.gallery {
  display: grid;
  gap: 1.25rem;
  grid-template-columns: repeat(6, 1fr);
  grid-auto-rows: minmax(120px, auto);
}

.work--full  { grid-column: span 6; }  /* volle breedte */
.work--half  { grid-column: span 3; }  /* helft */
.work--tall  { grid-row: span 2; }    /* hoog */

/* De blikvanger: enkel vanaf 900px, anders te druk */
@media (min-width: 900px) {
  .work--feature {
    grid-column: span 4;
    grid-row: span 2;
  }
}
/* C — masonry met CSS columns */
.masonry {
  columns: 1;
  column-gap: 1rem;
}
.masonry > * {
  break-inside: avoid;
  margin-bottom: 1rem;
}
@media (min-width: 768px) {
  .masonry { columns: 2; }
}
@media (min-width: 1200px) {
  .masonry { columns: 3; }
}

Nieuwe CSS heeft grid-template-rows: masonry, maar dat is nog niet overal ondersteund. Voor deze opdracht: gebruik columns of het editorial grid.

!
Editorial grid: de valkuil

Bij span-breedtes moet je altijd een fallback hebben voor smalle schermen: zet je grid op mobiel op 1fr en reset de spans.

@media (max-width: 767px) { .work--full, .work--half, .work--feature { grid-column: auto; grid-row: auto; } }

En: een editorial grid waarin zes items allemaal "feature" zijn, is gewoon een rommelige pagina. Kies één blikvanger.

07.C — Mini-cursus

Een sterke
projectdetailpagina
die draait op JS

Eén detailpagina per project kopiëren is dubbel werk en loopt gegarandeerd fout bij de eerste aanpassing. In deze mini-cursus bouw je één detailpagina die zijn inhoud uit een JavaScript-object haalt. Je project toevoegen wordt dan één blokje data — en je leert meteen hoe echte sites werken.

✓
Waarom dit de sterkste keuze is

Eén HTML-bestand (project.html), één databestand (js/projecten.js) en één script (js/project.js). Je opent een project via project.html?id=schoolfeest-2025. Nieuw werk toevoegen = één object in je lijst. Geen kopieerwerk, geen vergeten titels, geen kapotte links.

Les 1 — De data: één object per project

Begin bij de inhoud, niet bij de code. Elk project is een object met vaste sleutels. Houd de namen identiek voor elk project — daar rekent je script op.

// js/projecten.js
const projecten = [
  {
    id: 'schoolfeest-2025',
    titel: 'Schoolfeest 2025',
    categorie: 'Poster',
    jaar: '2025',
    tools: 'Illustrator, Figma',
    rol: 'Concept & vormgeving',
    intro: 'Een campagne voor het jaarlijkse schoolfeest, van affiche tot Instagram-post.',
    verhaal: [
      { kop: 'De opdracht', tekst: 'Het schoolfeest…' },
      { kop: 'Mijn aanpak', tekst: 'Ik vertrok van…' },
      { kop: 'Resultaat', tekst: 'Gedrukt op A2…' }
    ],
    beelden: [
      { src: 'assets/img/schoolfeest-1600.webp',
        alt: 'Definitieve poster, rood op zwart' },
      { src: 'assets/img/schoolfeest-schets.webp',
        alt: 'Potloodschets van drie postercomposities' }
    ],
    volgend: 'portretreeks-2024'
  },
  {
    id: 'portretreeks-2024',
    titel: 'Portretreeks',
    categorie: 'Fotografie',
    jaar: '2024',
    // … dezelfde sleutels, andere inhoud
    volgend: 'schoolfeest-2025'
  }
];
i
Regels voor je data
  • De id is uniek, in lowercase, met koppeltekens en zonder spaties of accenten. Die id komt in de URL.
  • Elk project heeft exact dezelfde sleutels. Ontbreekt er iets, dan valt het gat op in je pagina.
  • Tekst schrijf je tussen quotes. Gebruik je een apostrof binnen de tekst ('t), dan moet je ofwel het enkele quote-teken escapen (\') ofwel dubbele quotes nemen.
  • verhaal en beelden zijn arrays: daar kan je zoveel blokken in zetten als je wil.
  • Minstens drie blokken in verhaal: de opdracht, je aanpak, het resultaat. Dat is wat een detailpagina sterk maakt.
!
Let op de komma's

Tussen objecten en tussen eigenschappen staat een komma, maar niet na de laatste van een lijst. Een vergeten of te veel komma is de fout nummer één — je browser toont dan niets en de console geeft een SyntaxError.

Les 2 — De HTML: een skelet met vaste haken

Je detailpagina bevat de structuur en de lege plaatsen waar JavaScript straks inhoud zet. Elk element dat gevuld wordt, krijgt een id. Zo weet je script precies waar het moet schrijven.

Waarom een leeg skelet en geen verborgen inhoud?

Alles wat je via JavaScript vult, bestaat pas na het laden. Dat is hier bewust: dezelfde HTML bedient alle projecten. Zet er dus géén voorbeeldtekst in die blijft staan als je script faalt — je ziet dan meteen dat er iets mis is.

Volgorde van de scripts is belangrijk: eerst projecten.js (de data), dan project.js (de logica). Anders is de variabele projecten nog niet bekend.

!
Toegankelijkheid

Een schermlezer leest de pagina voor zodra hij geladen is. Omdat je titel pas daarna ingevuld wordt, moet je ook het <title>-element van de pagina aanpassen (dat doen we in les 3) en het laden niet eindeloos laten duren. Voor deze opdracht is dat voldoende.

Les 3 — Het script: id uitlezen, inhoud opbouwen

Nu komt het samen: lees de id uit de URL, zoek het juiste project, en vul elk blok. Dit is de volledige logica — minder dan vijftig regels, en je kan elke regel uitleggen.

// js/project.js

// 1. Welk project? De id staat in de URL: project.html?id=…
const params = new URLSearchParams(window.location.search);
const id = params.get('id');

// 2. Zoek dat project in de lijst
const project = projecten.find(p => p.id === id);

// 3. Bestaat het niet? Toon een nette melding.
if (!project) {
  document.querySelector('.project').innerHTML =
    '<h1>Project niet gevonden</h1>' +
    '<p><a href="index.html#werk">Terug naar alle werk</a></p>';
} else {
  toonProject(project);
}

// 4. Alle blokken vullen
function toonProject(p) {

  // Kop
  document.getElementById('kicker').textContent =
    `${p.categorie} · Schoolopdracht · ${p.jaar}`;
  document.getElementById('titel').textContent = p.titel;
  document.getElementById('intro').textContent = p.intro;

  // Titel van het browsertabblad
  document.title = `${p.titel} · Mijn portfolio`;

  // Metagegevens als <dt>/<dd>-paren
  const meta = document.getElementById('meta');
  const velden = [
    ['Jaar', p.jaar],
    ['Tools', p.tools],
    ['Rol', p.rol]
  ];
  meta.innerHTML = velden
    .map(([k, v]) => `<div><dt>${k}</dt><dd>${v}</dd></div>`)
    .join('');

  // Het verhaal: per blok een kop + alinea
  const verhaal = document.getElementById('verhaal');
  verhaal.innerHTML = p.verhaal
    .map(blok => `
      <h2>${blok.kop}</h2>
      <p>${blok.tekst}</p>`)
    .join('');

  // De beelden
  const galerij = document.getElementById('beelden');
  galerij.innerHTML = p.beelden
    .map(img => `
      <figure>
        <img src="${img.src}" alt="${img.alt}" loading="lazy">
      </figure>`)
    .join('');

  // Volgend project
  const volgende = projecten.find(q => q.id === p.volgend);
  const knop = document.getElementById('volgend');
  if (volgende) {
    knop.href = `project.html?id=${volgende.id}`;
    knop.textContent = `Volgend project: ${volgende.titel} →`;
  } else {
    knop.remove();
  }
}
i
De vier stukken die je moet begrijpen
  • URLSearchParams leest wat er na het vraagteken in de URL staat. ?id=schoolfeest-2025 levert 'schoolfeest-2025'.
  • find() loopt je lijst af en geeft het eerste project terug waarvan de id klopt. Geen match? Dan undefined.
  • textContent zet platte tekst — veilig. Gebruik het voor titels en koppen.
  • innerHTML zet HTML. Handig voor lijstjes, maar alleen met je eigen data. Nooit met iets wat een bezoeker intypt.
!
Template literals

De backtick ` laat je tekst en variabelen mengen met ${…}. Vergeet de backtick niet: met gewone quotes werkt ${…} niet en zie je letterlijk ${p.titel} op je scherm.

✓
Fout zoeken

Open DevTools → Console (F12). Een rode SyntaxError wijst op een komma of quote in je data. Een TypeError: Cannot read properties of null betekent dat een getElementById niets vond: dan klopt een id in je HTML niet met je script.

Vijf fouten die je hier gegarandeerd tegenkomt

1. Niets te zien. Je vergat de id in de URL: project.html zonder ?id=… toont "Project niet gevonden". Dat is correct gedrag, geen bug.

2. Alles leeg en een rode fout. Komma of quote in projecten.js.

3. "undefined" op je pagina. Een sleutel bestaat niet in je object (bv. p.jaren in plaats van p.jaar).

4. Links werken lokaal niet online. Gebruik relatieve paden (assets/img/…), geen absolute (/home/jij/…), en let op hoofdletters: GitHub Pages is hoofdlettergevoelig.

5. Niets gebeurt er. Je bent vergeten de twee <script>-tags toe te voegen, of de volgorde is omgekeerd.

Bonuspunten

Waarom dit "sterk" is

Je homepage en je detailpagina gebruiken nu dezelfde bron. Voeg je een project toe, dan verschijnt het meteen in je grid én werkt de detailpagina — zonder één extra regel HTML. Dat is precies het verschil tussen een site die je één keer bouwt en een site die je blijft onderhouden.

Verplicht voor deze opdracht is het niet: je mag ook drie losse detailpagina's schrijven. Maar wie dit doet, haalt gegarandeerd de topscore op Techniek, en heeft zijn site klaar voor de rest van zijn carrière.

10 — Afspraken

Eerlijk spel

Eigen werk

Je portfolio toont jouw werk. Gebruik je een afbeelding van iemand anders (bv. in je moodboard of als sfeerbeeld), vermeld je de bron. AI-gegenereerde beelden mogen als aanvulling, maar niet als vervanging van je eigen werk — en je vermeldt ze.

AI-gebruik

Codeerhulp van AI mag, zoals je ook een tutorial mag volgen. De regel is simpel: je moet elke regel kunnen uitleggen en verdedigen. Kopieer je een blok dat je niet begrijpt, dan is dat jouw verantwoordelijkheid — en het valt op in de verdediging. Vermeld AI-hulp in je reflectie.

Back-ups

Werk in je Git-repository en push minstens één keer per werkdag, ook als iets nog niet af is. Zo heb je altijd een back-up én een procesbewijs. "Mijn laptop is gecrasht" is geen geldig excuus en levert geen uitstel op — je code staat online.

11 — FAQ

Veelgestelde vragen

Ik heb echt geen zes grafische werken. Wat nu?

Kijk verder dan je schoolmap: foto's die je nam, een poster voor een fuif, een logo voor een vriend, een Instagram-post, een schetsboek, een 3D-experiment, een UI-oefening. Grafisch werk is breder dan "een affiche voor het vak". Heb je écht te weinig, dan maak je in overleg met je leerkracht twee extra werken — dat is evengoed geldig werk.

Waarom mag ik geen "Welkom op mijn website" schrijven?

Omdat het niets zegt. Elke portfolio op het internet begint zo, dus de zin onderscheidt jou nergens. Je bezoeker leert er niet uit wat je maakt, met welke tools je werkt of waarom het de moeite is om verder te scrollen.

Schrijf in plaats daarvan een zin die alleen over jouw werk kan gaan: een claim, een vraag, een getal, een statement of een concrete beschrijving. In de checklist vind je vijf vertrekpunten met voorbeelden. Let op: ook "Hallo en welkom!", "Welkom op mijn portfolio" en "Leuk dat je er bent" vallen onder dezelfde regel.

Mag ik een framework zoals Bootstrap of Tailwind gebruiken?

Standaard niet. Deze opdracht gaat over zelf layout bouwen — met Flexbox en Grid. Een framework zou de kern van de opdracht wegnemen. Wil je het toch om een goede reden, vraag het dan vooraf en schriftelijk. Bootstrap-templates van internet kopiëren is in elk geval geen optie.

Hoe lever ik precies in via GitHub?

Je maakt een openbare repository 6cm-portfolio-voornaam, commit en push je werk, zet GitHub Pages aan (Settings → Pages → Deploy from a branch → main / root) en bezorg de leerkracht twee links: die naar je repository en die naar je gepubliceerde site.

Zet in je README je naam, je klas, een korte omschrijving en de link naar je Figma-ontwerp. Je commitgeschiedenis is je procesbewijs: veel kleine commits zijn beter dan één grote upload op de laatste dag.

Moet mijn site echt online staan?

Ja. GitHub Pages is gratis en je hebt het in tien minuten onder de knie. Leren publiceren maakt deel uit van de opdracht: een portfolio dat alleen op je eigen schijf staat, bestaat niet voor de buitenwereld. Omdat je toch via GitHub inlevert, is GitHub Pages de logische keuze: één repository, twee vliegen.

Hoe groot moet mijn video zijn?

Maximaal 60 seconden en onder 25 MB, in MP4 (H.264). Zorg voor een posterbeeld (een screenshot uit de video) en een ondertitelbestand (.vtt). Je video moet afspelen op een smartphone zonder extra plugin, en zeker zonder dat de bezoeker eerst 50 MB moet downloaden.

Wat als mijn ontwerp niet overeenkomt met mijn code?

Dat mag deels — ontwerpen is geen 1-op-1 contract, en tijdens het coderen ontdek je altijd dingen. Maar de structuur en het kleur- en typografiesysteem moeten herkenbaar hetzelfde zijn, en je moet kunnen uitleggen waarom je afweek. Volledig losgekoppelde code die "toevallig" op je ontwerp lijkt, kost punten.

Ik ben sneller klaar dan de rest. Wat doe ik dan?

Kijk naar de bonussen in de rubriek: een eigen domein, een filter in je grid, dark mode, een 404-pagina. Of verhoog de lat: voeg een vierde detailpagina toe, maak een "case study" van je beste werk met procesbeelden, of verbeter je Lighthouse-score naar 100 op accessibility. Er is altijd een volgende stap.

Mag ik mijn portfolio later blijven aanvullen?

Graag zelfs. Dit is geen eindpunt maar een startpunt: je gebruikt deze site wellicht voor je stage, je hogere studies of je eerste klanten. Bewaar je Figma-bestand en je repository, en blijf werken toevoegen. Dat is precies wat een echte ontwerper doet.
